# ServicesNeedRestart

## What it means

For a day, a machine has had services (or, on pve01, containers) still running code
that an update replaced: the update is installed but not in effect. needrestart finds
them; `lab-restart-metrics` (roles/patching) reports them every 15 minutes as
`needrestart_service{unit=...}`. Nothing restarts them by itself, on purpose: needrestart
is in list mode on every lab machine (`/etc/needrestart/conf.d/50-lab.conf`).

## First five minutes

1. Which ones: the Machine dashboard for the host, or
   `needrestart_service{host="<host>"}` at https://lab.radicallydecent.com/prometheus/, or on
   the host itself `sudo needrestart -b -r l` (list only, safe to run any time).
2. Which update: `grep -A3 Start-Date /var/log/apt/history.log | tail -12` on the host
   (unattended security updates run around 06:00).
3. Kernel too? `needrestart_kernel_status` 2 or 3 means a newer kernel is installed: that
   takes a reboot ([RebootRequired](RebootRequired.md)).

## Common causes

- A security update of a library everything uses (glibc, zlib, OpenSSL) installed by
  roles/patching: every daemon linking it is listed.
- On pve01, `NEEDRESTART-CONT: LXC 106` means mgmt01's own processes are on old code
  too; that is mgmt01's own list, handled there.

## Escalate / fix

Restart what is listed, at a moment that suits what it carries, then refresh the metric
with `systemctl start lab-restart-metrics` and check the list is empty.

- Ordinary daemons (ssh, journald, logind, dbus-free services): `systemctl restart <unit>`.
  Restarting `ssh.service` keeps open sessions.
- `systemd-manager`: `systemctl daemon-reexec` (safe, no service restarts).
- dbus: don't restart it on a running system; it takes logind and desktops with it. It
  clears at the next reboot.
- mgmt01 `docker.service` / `containerd.service`: restarts every container (the portal's
  Guacamole sessions drop, Grafana and Prometheus blink). Pause the reconciler first
  (`touch /var/lib/lab/reconcile.paused`), check no operation is running (`lab status`),
  restart, check https://lab.radicallydecent.com/ and the probes, then remove the pause file.
- dc01 `samba-ad-dc` / `dnsmasq`: a few seconds without logins, DNS and DHCP. Pick a quiet
  moment; nobody should be building a machine.
- pve01 Proxmox daemons (`pveproxy`, `pvedaemon`, `pvestatd`, `pve-cluster`, firewall,
  HA): `systemctl restart` one at a time; VMs keep running. `pve-cluster` (pmxcfs) briefly
  makes /etc/pve read-only: never during a `lab` operation. Many at once, or a new kernel:
  plan a pve01 reboot instead ([RebootRequired](RebootRequired.md)).

Never set needrestart's restart mode to automatic on these machines (see
[KB-0156](../issues/KB-0156-needrestart-ubuntu-auto-restart.md)).
