# PortalWorkerStale

## What it means

The portal's worker hasn't recorded what Proxmox reports (/var/lib/lab/observed.json) for
over 5 minutes; normally it does every minute. Without it the portal's view of the machines
freezes, queued requests don't start, idle machines aren't hibernated, and lab-metrics
(the workstation targets) works from stale data.

## First five minutes

1. On mgmt01: `systemctl status lab-portal-worker` and
   `journalctl -u lab-portal-worker -n 100 --no-pager`.
2. Can it reach Proxmox? The Proxmox API probe on the Lab overview, or
   `curl -s -o /dev/null -w '%{http_code}\n' https://pve.radicallydecent.com:8006/`.
3. `ls -l --time-style=full-iso /var/lib/lab/observed.json`.

## Common causes

- The worker crashing in a loop on one bad record ([ServiceRestartLoop](ServiceRestartLoop.md)).
- pve01's API down or slow; the token in /etc/proxmox-lab/tofu.env rejected.

## Escalate / fix

- `systemctl restart lab-portal-worker` is safe: operations run as their own transient
  units (`lab-op-<id>`), so restarting the worker never interrupts a build or a delete.
- A crash on one record: the traceback names it (/var/lib/lab/guests/&lt;host&gt;.json). Fix
  the code in roles/portal; hand-edit a record only if you know what each field drives.
