# SecurityUpdatesPending

## What it means

A machine has had security updates waiting for a day. The counts come from
node_exporter's apt collector (`prometheus-node-exporter-apt.timer`, every 15 minutes).
Automatic security updates are set up by roles/patching.

```promql
sum by (host) (apt_upgrades_pending{origin=~".*-security.*"}) > 0
```

## First five minutes

1. `apt list --upgradable 2>/dev/null | grep -i security` on the host.
2. Are automatic updates running? `systemctl list-timers apt-daily-upgrade.timer`,
   `tail -50 /var/log/unattended-upgrades/unattended-upgrades.log`,
   `unattended-upgrade --dry-run -d 2>&1 | tail -30`.

## Common causes

- unattended-upgrades missing or not configured on that host.
- A package held back because it needs a decision (a changed config file, a new dependency).
- dpkg left half-done: `dpkg --audit`.

## Escalate / fix

- Ubuntu hosts: `unattended-upgrade -d` applies the security updates now.
- pve01 (Debian plus Proxmox): updates from the Proxmox repository are applied by hand,
  `apt update && apt full-upgrade` (never plain `apt upgrade` on Proxmox), when a reboot is
  possible: see [RebootRequired](RebootRequired.md).
- Updated libraries stay in memory until their services restart: restart those services,
  or reboot.
