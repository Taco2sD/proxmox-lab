# ReleaseFailedToApply

## What it means

The latest commit on `stable` failed to apply: the reconciler's run of ansible/site.yml or
the fleet's OpenTofu apply failed. The lab runs the previous configuration plus whatever
the failed run changed before it stopped. The reconciler tries again when `stable` moves,
and on its regular full run every 30 minutes.

## First five minutes

1. On mgmt01: `lab status`, and `cat /var/lib/lab/reconcile.json` (`failed_commit`).
2. The failed operation on the admin page (Activity), with its log:
   `ls -t /var/log/lab/*reconcile*.log | head -1 | xargs tail -60`.
3. The first `fatal:` or `FAILED` in that log names the task and host.

## Common causes

- A role change that passes the checks but fails on the real host (a package that doesn't
  exist there, a path only that host has, a service that won't start with the new config).
- A host unreachable during the run (dc01 or pve01: see [TargetDown](TargetDown.md)).

## Escalate / fix

- Roll forward: fix it in git, push to `main`; CI moves `stable` and the reconciler applies
  it. Revert the commit if the fix will take longer.
- Don't edit files under /opt/proxmox-lab on mgmt01: it's the reconciler's checkout of
  `stable`, reset on every run.
