# TargetDown

## What it means

Prometheus asked a target for its metrics for 3 minutes and got nothing (`up == 0`):
a server's or workstation's node_exporter (jobs `servers`, `workstations`) or the Proxmox
exporter (job `proxmox`). Workstations that are meant to be off are not targets
(lab-metrics lists only running, built machines), so a workstation here is one that
should be answering.

```promql
up{job=~"servers|workstations|proxmox"} == 0
```

## First five minutes

1. Which target, and the scrape error: https://lab.radicallydecent.com/prometheus/targets (the error column).
   `connection refused` = the machine is up but the exporter isn't; `context deadline
   exceeded` or `no route to host` = the machine itself isn't answering.
2. Is the VM running? On pve01: `qm list` (dc01 is VM 105, workstations 131-159) or
   `pct status 106` for mgmt01. The admin page shows a workstation's power state too.
3. From mgmt01: `curl -s --max-time 5 http://<ip>:9100/metrics | head -3`.
4. On the machine: `systemctl status prometheus-node-exporter`. Workstations: on pve01,
   `qm guest exec <vmid> -- systemctl status prometheus-node-exporter`.
5. Job `proxmox`: on mgmt01, `docker compose -f /etc/lab-monitoring/compose.yml logs --tail 50 pve-exporter`;
   on pve01, `systemctl status pveproxy`.

## Common causes

- The VM is hung or frozen: nested VMs stop when the Windows host sleeps or is
  overloaded. Look at its console in the Proxmox UI (https://pve.radicallydecent.com)
  before doing anything to it.
- node_exporter stopped, or not installed yet: workstations get it from their
  configuration run (roles/node_exporter, through ansible/local.yml).
- pve-exporter: its token (`/etc/lab-monitoring/pve.env`, made by roles/pve_monitoring)
  revoked, or the Proxmox API down.

## Escalate / fix

- Exporter down: `systemctl restart prometheus-node-exporter`, then read
  `journalctl -u prometheus-node-exporter -b` for why it stopped.
- VM hung, after checking its console: `qm reset <vmid>` (a hard reset, like the power
  button) for a workstation. dc01 is the only domain controller (DNS, DHCP and sign-ins
  stop meanwhile) and mgmt01 runs the portal and the reconciler: announce before
  resetting either.
- Never `qm destroy` to "fix" a machine: deletes go through the admin page, which also
  removes its AD account, DHCP reservation and DNS records.
