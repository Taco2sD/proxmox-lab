# RebootRequired

## What it means

A machine has needed a reboot for a day: an updated kernel or core library is installed
but not running (`/var/run/reboot-required` exists).

## First five minutes

1. Why: `cat /var/run/reboot-required.pkgs` on the host.
2. What the reboot interrupts (below), and whether anyone is using the machine now (the
   workstation table's "Last used", or `who`).

## Common causes

- Automatic security updates (roles/patching) installed a new kernel, glibc or systemd;
  they never reboot by themselves.
- A manual `apt full-upgrade` on pve01 brought a new Proxmox kernel.

## Escalate / fix

Reboot at a planned moment, then confirm the machine is back on the Lab overview: up,
its key services active, its probes green. What each reboot interrupts:

- A workstation: only its owner. Restart it from My lab or the admin page.
- dc01: the only domain controller. DNS, DHCP, Kerberos and LDAP stop for a minute or
  two; open sessions carry on. Pick a moment when nobody is building a machine.
- mgmt01: the portal, Guacamole, Grafana and the reconciler stop for a minute. First check
  no operation is running (`lab status`, the admin page's Activity).
- pve01: everything. Plan it: check /etc/default/grub.d/ holds no leftover installer file
  (one once broke `update-grub` and left a bare `grub>` prompt), say when, and keep the
  Hyper-V console open on the Windows host.
