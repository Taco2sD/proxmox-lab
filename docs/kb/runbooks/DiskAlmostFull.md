# DiskAlmostFull

## What it means

A real filesystem (not tmpfs or overlay) has had under 10% free for 5 minutes.

## First five minutes

1. `df -h` on the host, then the biggest directories:
   `du -xh --max-depth=2 <mountpoint> 2>/dev/null | sort -h | tail -20`.
2. mgmt01 (14 GB root): `docker system df`, `journalctl --disk-usage`,
   `du -sh /var/lib/lab-monitoring/prometheus /var/lib/docker /var/log/lab /var/lib/lab`.
3. pve01: `pvesm status`. ISOs and backups live on `local` (/var/lib/vz); nightly backups
   of dc01 and mgmt01 keep the last 7 (roles/pve_backups).

## Common causes

- mgmt01: container images (Grafana's is about 2 GB), Prometheus's data (capped at 2 GB by
  `--storage.tsdb.retention.size` in ansible/roles/monitoring/templates/compose.yml.j2),
  operation logs.
- A log growing without rotation; the journal (`journalctl --vacuum-size=200M`).
- Workstations: the owner's own files (24 GB thin disks).

## Escalate / fix

- Safe to remove: unused Docker images (`docker image prune` keeps the ones in use), old
  journal files, old operation logs in /var/log/lab (the records in /var/lib/lab/ops stay).
- Never delete /var/lib/lab (the runner's state: guest records, OpenTofu states,
  passwords) or Prometheus's data directory by hand.
- Grow mgmt01's root online, from pve01: `pct resize 106 rootfs +4G` (the thin pool must
  have room: [StoragePoolAlmostFull](StoragePoolAlmostFull.md)). A workstation's disk size
  comes from its catalog role (`size.disk_gb`), which OpenTofu owns: change it there.
