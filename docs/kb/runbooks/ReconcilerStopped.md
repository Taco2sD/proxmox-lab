# ReconcilerStopped

## What it means

`lab-reconcile.timer` on mgmt01 hasn't started the reconciler for over 5 minutes. The
reconciler (`lab reconcile`) deploys the servers and applies the fleet whenever `stable`
moves; while it's stopped, merged changes don't reach the lab and drift isn't repaired.

The timer is `OnUnitInactiveSec=1min`: it fires a minute after the previous run *ends*,
so it doesn't trigger while a run is going. The rule therefore ignores a run that has been
active for under an hour (a long ansible/site.yml deploy), and fires for one running
longer: that one is stuck.

```promql
(time() - node_systemd_timer_last_trigger_seconds{host="mgmt01",name="lab-reconcile.timer"} > 300)
  unless on ()
(node_systemd_unit_state{host="mgmt01",name="lab-reconcile.service",state="active"} == 1
  and on () time() - node_systemd_unit_start_time_seconds{host="mgmt01",name="lab-reconcile.service"} < 3600)
```

## First five minutes

1. On mgmt01: `systemctl status lab-reconcile.timer lab-reconcile.service`. Active for
   over an hour means stuck; inactive with the timer not waiting means stopped.
2. `journalctl -u lab-reconcile -n 50 --no-pager`: the last task it was on.

## Common causes

- A run stuck on one task (an Ansible task waiting for an unreachable host): the service
  stays active far longer than usual.
- The timer was disabled, or mgmt01 just rebooted (`OnBootSec=2min`).

## Escalate / fix

- A stuck run: find the hanging task in `journalctl -u lab-reconcile`, fix its cause, then
  `systemctl stop lab-reconcile.service`; the timer starts a fresh run a minute later.
- Timer off: `systemctl enable --now lab-reconcile.timer` (roles/runner installs it).
