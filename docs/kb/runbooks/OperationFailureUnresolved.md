# OperationFailureUnresolved

## What it means

A lab operation failed and nothing has put it right since. Operations are what `lab` does:
guest builds and deletes, reimages, image builds, reconciles; each has a record in
/var/lib/lab/ops/, a log in /var/log/lab/&lt;op&gt;.log, and a line in the admin page's Activity.
lab-metrics (ansible/roles/monitoring/files/lab-metrics) groups them by subject: the
machine, the image kind (`image headless`, `image desktop`) or the `release` (reconciles).
A failure is resolved by a later successful operation on the same subject, of any kind
(a successful delete resolves a failed build of that machine). Failures already followed
by a success never fire, however recent; a failure on one machine isn't hidden by a
success on another. Operations stopped by hand count as failed.

```promql
lab_operation_unresolved_failure_timestamp_seconds > 0
```

Labels: `kind` (the operation), `subject`, `op` (its ID). The value is when it failed.
`lab_operations_unresolved` is the count, shown on the Lab overview.

## First five minutes

1. The log, on mgmt01: `tail -80 /var/log/lab/<op>.log` (the `op` label), or open the
   operation on the admin page's Activity. The first `fatal:`, `FAILED` or `Error:` names
   the cause.
2. The record: `cat /var/lib/lab/ops/<op>.json` (`error`, `steps`: how far it got).
3. Where things stand now: `lab status` (machines vs. what should exist).

## Common causes

- A guest build: Proxmox out of memory or storage ([MemoryLow](MemoryLow.md),
  [StoragePoolAlmostFull](StoragePoolAlmostFull.md)), dc01 unreachable during the AD steps,
  the clone's first configuration run failing.
- An image build: the installer itself (the image factory installs over PXE into RAM:
  its memory limits have bitten before).
- `release`: the same as [ReleaseFailedToApply](ReleaseFailedToApply.md).

## Escalate / fix

- Fix the cause, then run the same thing again: rebuild or delete the machine from the
  admin page or My lab, `lab image build <kind>`, or push a fix for the release. The alert
  clears when that succeeds.
- A machine that will never be needed again: deleting it through the admin page is a
  success on that subject and resolves the alert. Don't delete operation records to
  silence it: they are the lab's audit trail (with /var/lib/lab/audit.jsonl).
