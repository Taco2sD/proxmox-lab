# ServiceProbeFailed

## What it means

blackbox_exporter on mgmt01 checked a service the way a user would, and it has failed for
2 minutes. The `probe` label says which. The probes are defined in
ansible/roles/monitoring/templates/prometheus.yml.j2 (job `probes`) and their modules in
ansible/roles/monitoring/templates/blackbox.yml.j2. TLS probes also fail on an invalid or
expired certificate.

| probe | checks | served by |
|---|---|---|
| Portal | https://lab.radicallydecent.com/ from mgmt01 | nginx on mgmt01, then `lab-portal.service` (127.0.0.1:8090) |
| Guacamole | /guacamole/ | nginx, then the Guacamole container (127.0.0.1:8085) |
| Grafana | /grafana/api/health | nginx, then the Grafana container (127.0.0.1:3000) |
| Proxmox API | https://pve.radicallydecent.com:8006/ | `pveproxy` on pve01 |
| Public sign-in (VPS) | the VPS, by address, with the real name | nginx + oauth2-proxy on the VPS (vps/README.md) |
| LDAPS (dc01) | dc01.lab.radicallydecent.com:636, TLS handshake | `samba-ad-dc` on dc01 |
| Kerberos (dc01) | 10.10.10.5:88, TCP connect | `samba-ad-dc` |
| DNS (dc01) | an A query for dc01.ad.lab.internal at 10.10.10.5 | `samba-ad-dc` (its internal DNS) |

## First five minutes

1. Which probe, since when: Lab overview, Service checks panel.
2. Re-run the probe with its log, on mgmt01 (use the failing series' `module` and
   `instance` labels):
   `curl -s 'http://127.0.0.1:9115/probe?module=https&target=https://lab.radicallydecent.com/&debug=true'`
3. Try it by hand from mgmt01: `curl -sv -o /dev/null https://lab.radicallydecent.com/`,
   `dig @10.10.10.5 dc01.ad.lab.internal`,
   `openssl s_client -connect dc01.lab.radicallydecent.com:636 </dev/null`.
4. Is the service behind it up? mgmt01: `systemctl status lab-portal nginx`,
   `docker compose -f /etc/lab-monitoring/compose.yml ps`, `docker ps` (Guacamole runs from
   /etc/lab-portal/guacamole/compose.yml). dc01: `systemctl status samba-ad-dc`.
   pve01: `systemctl status pveproxy`.

## Common causes

- A service restarted or crashed: the Key services panel on the Lab overview, then
  `journalctl -u <unit> -b` on its host.
- An expired certificate: see [CertificateExpiresSoon](CertificateExpiresSoon.md).
- Public sign-in only: the VPS or its nginx is down, or the lab's own way out (the
  Windows host's Wi-Fi). Inside the lab, everything else keeps working.

## Escalate / fix

- Restart the one service that is down, then watch the probe recover on the panel.
- Several probes failing together point at one shared piece: nginx on mgmt01 (Portal,
  Guacamole, Grafana) or samba-ad-dc on dc01 (LDAPS, Kerberos, DNS).
