# WorkstationNotCheckingIn

## What it means

A running workstation, up for over two hours, hasn't finished a configuration run in over
two hours. Workstations run `ansible-pull` from the `stable` branch every 30 minutes
(`pull_interval`) and report each finished run to mgmt01 (`/lab-events/configured`,
logged in /var/log/nginx/lab-events.log, kept in /var/lib/lab/checkins.json). No report
means the machine is drifting away from git.

## First five minutes

1. The workstation table's Configured column: one machine, or all of them?
2. Its last run: on pve01, `qm guest exec <vmid> -- journalctl -u ansible-pull -n 100 --no-pager`.
3. Start a run now: the admin page's "Run configuration", or on pve01
   `qm guest exec <vmid> -- systemctl start --no-block ansible-pull.service`.

## Common causes

- Every workstation at once: the `stable` branch has a change that fails on workstations
  (ansible/local.yml and its roles), or GitHub is unreachable.
- One machine: its clock (TLS and Kerberos fail: [ClockSkew](ClockSkew.md)), its AD join,
  a full disk, or a run stuck on apt (`ps aux | grep -E 'apt|dpkg'`).
- The run finishes but its report never arrives: mgmt01's nginx (`/lab-events/`).

## Escalate / fix

- Fix the playbook in git; the next pull picks it up.
- A broken machine: its owner can delete it and make a new one; fleet machines can be
  rebuilt with `lab reimage <host>` on mgmt01.
