# GuestMemoryBudgetNearlyUsed

## What it means

Over 90% of the memory the portal may hand out to workstations (`guest_memory_mb` in
ansible/group_vars/all.yml) is promised to existing machines. The portal refuses a new
workstation that doesn't fit (`admission()` in ansible/roles/runner/files/lablib.py).
Hibernated machines count: they need their memory back when they wake.

```promql
lab_guest_memory_committed_bytes / lab_guest_memory_budget_bytes > 0.90
```

## First five minutes

1. Lab overview: the Guest RAM gauge and the workstation table (owner, role, last used).
2. On mgmt01: `lab status` lists every machine and whether its VM is running.

## Common causes

- Test machines left behind; people with a desktop plus several dev boxes.

## Escalate / fix

- Delete machines nobody uses on the admin page (ask their owners first: their files go too).
- Raise `guest_memory_mb` only if pve01 really has the memory (see [MemoryLow](MemoryLow.md)),
  and in git, not on mgmt01.
