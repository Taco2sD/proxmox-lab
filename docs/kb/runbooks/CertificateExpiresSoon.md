# CertificateExpiresSoon

## What it means

A certificate the probes see expires within 14 days. Let's Encrypt certificates are renewed
30 days before they expire, so renewal has been failing for over two weeks. All of them
use DNS-01 through acme-dns on the VPS (ansible/roles/acme_cert/tasks/main.yml explains why).

| probe | certificate | renewed by |
|---|---|---|
| Portal, Guacamole, Grafana | lab.radicallydecent.com on mgmt01 | `certbot.timer` on mgmt01; hook /usr/local/sbin/certbot-acme-dns-hook; account in /etc/lab-portal/acme-dns |
| LDAPS (dc01) | dc01.lab.radicallydecent.com on dc01 | `certbot.timer` on dc01; its deploy hook /usr/local/sbin/samba-tls-deploy restarts samba-ad-dc |
| Proxmox API | pve.radicallydecent.com on pve01 | Proxmox's own ACME client (plugin `acmedns`), run daily by `pve-daily-update.timer` |
| Public sign-in (VPS) | lab.radicallydecent.com on the VPS | certbot on the VPS (vps/README.md) |

## First five minutes

1. Which one, days left: https://lab.radicallydecent.com/prometheus/graph?g0.expr=(probe_ssl_earliest_cert_expiry-time())/86400
2. mgmt01 or dc01: `certbot certificates`, then `certbot renew --dry-run` and read the error.
3. pve01: `pvenode cert info` and `journalctl -u pve-daily-update -n 50`.
4. On mgmt01, `lab doctor` prints the days left for the three lab certificates.

## Common causes

- acme-dns on the VPS down or unreachable (acme-ns.radicallydecent.com): every renewal
  fails at once.
- An acme-dns account file missing after a rebuild (docs/operations.md, "Secrets").
- The deploy hook failed: the new certificate exists but the service still serves the old
  one (`systemctl reload nginx`, `systemctl restart samba-ad-dc`).

## Escalate / fix

- Fix the cause, renew (`certbot renew` on mgmt01/dc01, `pvenode acme cert renew` on pve01),
  and check the probe's expiry date moved.
- The VPS also hosts the website: change only what the lab needs there.
