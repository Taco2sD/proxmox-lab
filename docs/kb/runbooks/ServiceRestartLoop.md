# ServiceRestartLoop

## What it means

systemd restarted a service more than 3 times in 15 minutes (its `Restart=` setting).
Each restart looks like recovery, so the unit never shows as failed: this alert is the
only sign of a crash loop.

```promql
increase(node_systemd_service_restart_total[15m]) > 3
```

## First five minutes

1. `systemctl status <unit>` and `systemctl show <unit> -p NRestarts -p ExecMainStatus`.
2. `journalctl -u <unit> -b -n 100`: the lines just before each "Scheduled restart job".
3. Did a deploy just change it? On mgmt01, `journalctl -u lab-reconcile --since -1h`, and
   the latest operations on the admin page.

## Common causes

- A bad configuration from a deploy (the portal's `lab-portal` and `lab-portal-worker`
  restart on failure every 10 seconds).
- A dependency that is down: dc01 for anything that signs in to AD, the Proxmox API for
  the worker.
- Out of memory: `journalctl -k -b | grep -i oom`.

## Escalate / fix

- Roll forward: fix the role in git, push, let the reconciler deploy it. Hand edits on a
  server are overwritten by the next deploy: if one must hold for a while, pause the
  reconciler first (`touch /var/lib/lab/reconcile.paused` on mgmt01) and remove the file
  afterwards.
