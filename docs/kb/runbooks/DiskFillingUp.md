# DiskFillingUp

## What it means

At the rate of the last 6 hours, a filesystem that is already over 60% full runs out
within a day. It fires before [DiskAlmostFull](DiskAlmostFull.md), while there is time.

```promql
predict_linear(node_filesystem_avail_bytes[6h], 86400) < 0
  and node_filesystem_avail_bytes / node_filesystem_size_bytes < 0.40
```

## First five minutes

1. The trend: Machine dashboard (https://lab.radicallydecent.com/grafana/d/lab-machine/machine?var-host=&lt;host&gt;), Filesystems and Disk I/O.
2. What is growing: `find <mountpoint> -xdev -mmin -60 -size +50M -ls`, or
   `du -xh --max-depth=2 <mountpoint> | sort -h | tail` twice, a few minutes apart.

## Common causes

- A log in a loop: a service failing every few seconds writes the same lines forever.
- An image build or a backup in progress (pve01; temporary).
- Prometheus after new targets: it levels off at its 2 GB cap.

## Escalate / fix

- Stop the writer, then clean up as in [DiskAlmostFull](DiskAlmostFull.md).
- A one-off that will end (a backup run): note it and let the alert resolve.
