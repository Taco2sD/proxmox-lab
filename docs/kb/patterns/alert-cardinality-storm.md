# One alert per item explodes into hundreds

## What happens

An alert expression that keeps a high-cardinality label (unit name, file system, connection) fires
one alert per series. A single cause (a retry loop, one bad setting on every host) produces hundreds
of alerts at once: the alert list becomes unreadable and real alerts drown.

## How to spot it

- `count by (alertname) (ALERTS{alertstate="firing"})` dominated by one rule.
- The rule has no `count by` / `max by` over the noisy label.

## How to fix

Aggregate to the level someone acts on, usually the host:
`count by (host) (node_systemd_unit_state{state="failed"} == 1)`. Put the per-item detail on a
dashboard (the Machine dashboard's failed-units table), not in the alert.

## How to prevent

Every alert names its unit of action (host, service, certificate) in a `by` clause. Try a new rule
against today's data first: `count(<expr>)` should be small.
