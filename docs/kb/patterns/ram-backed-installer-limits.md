# Work done inside a RAM-backed installer runs out of memory

## What happens

Ubuntu's netboot installer keeps the downloaded ISO and its own root filesystem in RAM (tmpfs). Anything that adds to that, or takes memory away, fails in ways that look unrelated: "No space left on device", a hung package install, a kernel panic "System is deadlocked on memory".

## How to spot it

- The installer console shows ENOSPC, an OOM kill, or stops making progress during package installation.
- The VM had a ballooning range (`qm config <vmid> | grep balloon`) or less RAM than ISO plus target system.

## How to fix

Give the installer fixed memory with room for the ISO (`initramfs_options=size=90%` raises the tmpfs cap), and move heavy package installs to the installed system's first boot.

## How to prevent

Keep the installer stage minimal: the image factory installs a base system, the builder's first boot does the rest, and workstations never run the installer (they clone the golden image). No ballooning on VMs that install.
