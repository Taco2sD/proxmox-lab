# Work in flight is lost when the process holding it restarts or dies

## What happens

Something long-running lives inside a process that is restarted routinely, or its bookkeeping depends on the doer finishing: builds as children of the worker (killed by every deploy), operations whose `lab` process died staying In progress forever, Ansible dropping notified handlers when a play fails.

## How to spot it

- Operations stuck In progress on the admin page while `systemctl list-units 'lab-op-*'` shows nothing.
- A deployment that succeeded on the next run but still runs old code.

## How to fix

Run long work in its own unit (`lab-op-<id>`), have a reaper close records whose process is gone, and set `force_handlers = True`.

## How to prevent

Assume every process can be restarted at any moment; state that only the doer updates needs a check that the doer is alive.
