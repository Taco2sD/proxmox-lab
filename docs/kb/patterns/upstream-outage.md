# An outside service the lab depends on is briefly down

## What happens

A step fetches something from a service the lab doesn't run (GitHub's release downloads,
Docker Hub, Ubuntu's archive, Let's Encrypt) and that service answers with an error for a
while. Without retries, a transient outage looks like a broken change: CI goes red, a
deploy stops halfway, a certificate renewal is skipped.

## How to spot it

- The failing step is a download or an API call, the error is a 5xx or a timeout, and
  the same request from another machine fails too (`curl -sI <url>`).
- Nothing in the change touches that step.

## How to fix

Retry with a delay for transient errors (`curl --retry N --retry-delay S
--retry-all-errors`, Ansible's `retries`/`until`), then re-run. Don't loosen checksum or
certificate verification to get past it.

## How to prevent

Retries on every fetch from outside; pinned versions with checksums, so a retried
download is still the exact file; for things fetched often, a local copy (a package
cache, pre-pulled images pinned by digest).
