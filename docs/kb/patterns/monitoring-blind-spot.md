## What happens

The dashboards are green because the thing that broke isn't measured, is measured only as
a panel nobody watches, or fires an alert that has no receiver. Typical shapes:

- the check covers the failure state but not the desired state (a unit that is *failed*
  alerts, one that is *stopped* doesn't)
- a protocol answers while the data behind it is unhealthy (LDAP answers, the AD database
  has errors)
- the monitoring runs on the host it monitors, so its own outage reads as silence
- alerts exist, but nothing delivers them

## How to spot it

For each component in `docs/kb/components.yml`, ask "if this stopped right now, which
alert fires, and who gets it?" Then test the answer for real: stop one service in a quiet
moment and time the alert. Useful queries:

- `node_systemd_unit_state{state="active"} == 0` for the units that must run
- `count(ALERTS{alertstate="firing"})`, and compare it with what actually reached a person

## How to fix

Add the missing signal at the highest level that captures it (a probe beats a process
check, and a health check the application provides beats a probe). Give every alert a
runbook and a receiver, and watch the watcher from somewhere else (a dead man's switch).

## How to prevent

A new component isn't finished until its "what alerts if this stops?" question has an
answer in alerts.yml and a runbook in docs/kb/runbooks/.
