# CI passes but the deployment fails

## What happens

The checks validate YAML, Ansible syntax, Python and OpenTofu, but some errors only appear when a template is rendered or a service parses its configuration on the target: an unquoted nginx regex, a lookup used as a Jinja filter, a template naming a removed variable. CI is green, `stable` moves, and the reconciler's deploy (or a workstation's run) fails.

## How to spot it

- A reconcile operation failed right after a green CI run (admin page Activity, ReleaseFailedToApply).
- WorkstationNotCheckingIn on every running workstation after a release.

## How to fix

Fix forward with a new commit; validation before reload (`nginx -t` in the handler) usually keeps the running service intact meanwhile.

## How to prevent

Add the failing class to `tools/check` where it can run without the target (render templates with test variables, `nginx -t` against a scratch config), and keep validate-before-reload on every service.
