# A client retries forever against something meant to be off

## What happens

A client with automatic reconnect (Guacamole's browser client, a dashboard tab, a polling script)
stays open while its target goes away on purpose: a hibernated VM, a moved service, a retired URL.
It retries every few seconds for hours or days, producing log noise, failed units, 404s and load.
Nothing is broken, but the noise hides real failures and feeds other problems
([per-connection-unit-pileup](per-connection-unit-pileup.md)).

## How to spot it

- The same client (address, user, user agent) in logs at a steady interval:
  `docker logs guacamole-guacamole-1 | grep 'connected to connection'`
- Repeating 404s for paths that don't exist on that host in nginx's access log.
- `journalctl -u 'lab-console@*' --since -1h | grep -c 'not running'`

## How to fix

Server side: answer the retry cheaply and clearly (exit 0 with a log line, HTTP 410), and end the
sessions or credentials pointing at a target that was turned off on purpose. Client side: close the
tab. Note the client in the issue so the next person recognises it.

## How to prevent

Code that switches something off on purpose (hibernate, retire a name) also ends the sessions that
point at it, and logins carry an expiry.
