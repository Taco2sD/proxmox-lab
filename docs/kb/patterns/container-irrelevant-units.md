# Units that can't work in a container fail there

## What happens

An LXC container runs a full distribution, including units meant for hardware or kernel features
it doesn't have: NVMe-oF autoconnect, chrony (the host owns the clock), udev triggers, kernel
module loaders. They fail at every boot and clutter `systemctl --failed`, hiding real failures.

## How to spot it

- `systemd-detect-virt -c` says `lxc`, and the failed unit's journal mentions `/dev`, kernel modules
  or "Operation not permitted" on the clock.
- PromQL, failures only the container has: `node_systemd_unit_state{host="mgmt01",state="failed"} == 1`

## How to fix

Mask the unit in the role that owns the container's own configuration
(`ansible.builtin.systemd_service` with `masked: true`), with a comment naming the missing feature.
Masking is explicit and survives package upgrades; disabling doesn't stop static units.

## How to prevent

When a host becomes a container, or a new package lands on one, list failed units after the next
boot and decide for each: needed, or masked with a reason. The failed-units alert catches the rest.
