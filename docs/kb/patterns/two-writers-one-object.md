# Two writers fight over one object

## What happens

Two parties manage the same thing with different ideas: Ansible wrote sssd.conf as 0600 while sssd.service resets it to root:sssd 0640 at every start; workstations and the DHCP server both registered the same DNS names, and AD gives a name to whoever created it first. The result is endless "changed" runs or refused updates.

## How to spot it

- A configuration run reports the same change every time.
- REFUSED or permission errors for an object that exists and looks right.
- `samba-tool dns query` shows a record you didn't create, or an empty tombstoned name.

## How to fix

Pick one writer. Match the state the other party enforces, or stop it writing (SSSD `dyndns_update = False`), and remove what the old writer left behind.

## How to prevent

Write down who owns each object (docs/boundaries.md) and keep it to one owner.
