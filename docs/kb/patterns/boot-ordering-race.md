# A unit runs before what it needs is ready

## What happens

At boot a unit starts before something it needs but doesn't declare (`After=`, `Wants=`): a network
manager, a mount, a socket, a directory under /run. It fails once and is never retried, so the
failure sits there while the system looks healthy, and units ordered after `network-online.target`
may have started early.

## How to spot it

- The failure time is the boot time: `systemctl show <unit> -p ExecMainExitTimestamp` against
  `uptime -s`; `journalctl -b -u <unit>`.
- `systemd-analyze critical-chain <unit>`, `systemctl list-dependencies <unit>`.

## How to fix

Declare the missing ordering in a drop-in (`/etc/systemd/system/<unit>.d/`), or disable the unit if
what it waits for isn't used on that host. Verify with `systemd-analyze verify`, and with a reboot
when one is acceptable.

## How to prevent

Roles that change how a host does networking, mounts or time also check what's ordered after them.
Failed-units monitoring catches one-off boot failures that would otherwise wait for the next reboot.
