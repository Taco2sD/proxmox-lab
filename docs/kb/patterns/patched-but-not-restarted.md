# An update is installed but the running processes still use the old code

## What happens

A package update replaces files on disk. Every process that loaded the old library or
binary keeps running it from memory until it restarts. Patch reports and `apt` say the
machine is up to date, yet the vulnerable code is still the code that runs. Automatic
security updates make this the normal state: they install, they don't restart (and in
this lab they must not: see [KB-0156](../issues/KB-0156-needrestart-ubuntu-auto-restart.md)).

## How to spot it

- `needrestart_services` / `needrestart_containers` per host (roles/patching:
  lab-restart-metrics); the [ServicesNeedRestart](../runbooks/ServicesNeedRestart.md) alert.
- On a host: `sudo needrestart -b -r l`, or the raw signal it reads:
  `sudo grep -l '(deleted)' /proc/[0-9]*/maps` (processes mapping deleted files).
- Kernel: `needrestart_kernel_status` 2 or 3; `node_reboot_required`.

## How to fix

Restart the listed services at a moment that suits each (the runbook says what each one
interrupts here), or reboot when the list is long or includes the kernel.

## How to prevent

You don't prevent it; you make it visible and give it a deadline: report it per host,
alert after a grace period, and fold restarts into planned maintenance.
