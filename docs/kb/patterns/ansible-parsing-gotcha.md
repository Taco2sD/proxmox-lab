# Ansible parses a task differently than it reads

## What happens

Some Ansible syntax looks fine and fails late, at run time: free-form module arguments (`shell: |`
with backslash line continuations or quoted `key=value`-like text) go through Ansible's own argument
splitter; Jinja is evaluated inside strings meant literally. The playbook passes lint and fails on
the host, or does something other than it reads.

## How to spot it

- "failed at splitting arguments, either an unbalanced jinja2 block or quotes" on a `shell` task.
- A task changes something unexpected: rerun with `-vvv` and read the arguments the module got.

## How to fix

Pass scripts under the `cmd:` key (`ansible.builtin.shell:` with `cmd: |` and `executable:`), which
Ansible never splits; wrap literal `{{ }}` in `{% raw %}`.

## How to prevent

New shell tasks use the `cmd:` form. Run a changed role against a real host before pushing:
ansible-lint can't see run-time parsing.
