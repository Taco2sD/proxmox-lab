# A single-file bind mount keeps serving the old file

## What happens

Docker bind-mounts a single file by inode. Ansible's copy and template modules (and most editors)
replace a file by writing a new one and renaming it over the old: the path now names a new inode,
but the container still has the old one. A reload (SIGHUP) re-reads stale content; only recreating
the container picks up the change. Everything looks deployed, and nothing changes.

## How to spot it

- Host and container disagree: `sha256sum /etc/x/file; docker exec <c> sha256sum /path/in/container`
- `docker inspect <c> --format '{{json .Mounts}}'` shows a file, not a directory, as Source.
- Prometheus: `/api/v1/rules` still lists the old rule names after a deploy.

## How to fix

Mount the directory that holds the file (`/etc/lab-monitoring/prometheus:/etc/prometheus:ro`),
recreate the container once, and remove the old single-file paths.

## How to prevent

Compose files in this repo mount configuration by directory (the rule is written down in
ansible/roles/monitoring/templates/compose.yml.j2). After a deploy, check that the service reports
the new configuration (rules API, config hash), not just that the file changed.
