## What happens

A quick `pct set`, `qm set`, UI click, `pvenode` call or edit on the VPS fixes something
now. The repo never hears about it, so a rebuild from git produces a machine that's
different and usually broken, and the next person can't tell the setting was deliberate.

## How to spot it

Compare the live config with git: `pct config <id>`, `qm config <id>`, `pvenode config get`,
`cat /etc/pve/firewall/cluster.fw`, the Hyper-V VM's settings. Read the shell history of
recent fixes. Grep the repo for the values. A value that appears only in a comment or a
KB page is hand-made state.

## How to fix

Bring it under a tool that both creates and checks it: OpenTofu `import` blocks for VMs and
containers, Ansible for files and API calls (with a check mode), or at minimum a
`lab doctor` comparison against group_vars.

## How to prevent

Rule: every hand change gets, the same day, either a commit that makes it reproducible or a
KB issue that says why it can't be (yet).
