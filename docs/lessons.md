# Things that broke, and why

Most of the learning was here. Each of these is fixed in the code. This page is the short
version; every row links to its page in the knowledge base ([docs/kb/](kb/)), which has the
symptom, how it was found, the root cause, the fix and its commit, how it was verified, and
what now prevents it. The knowledge base also groups problems into recurring patterns
([docs/kb/patterns/](kb/patterns/)) and holds the ones found since, many of them by the
monitoring (docs/monitoring.md).

| Symptom | Cause | Fix | Details |
|---|---|---|---|
| UEFI VM has no network boot option at all | Since the 2024 PixieFail fixes, EDK2's network stack won't start without an entropy source; the default Proxmox CPU type doesn't expose RDRAND | Give VMs a virtio RNG (`--rng0 source=/dev/urandom`) | [KB-0020](kb/issues/KB-0020-uefi-vm-no-network-boot-without-rng.md) |
| Netboot installer: "No space left on device" even at 7 GB RAM | Ubuntu's `url=` netboot downloads the ISO into the initramfs rootfs, a tmpfs capped at 40% of RAM on this kernel | `initramfs_options=size=90%` on the installer's kernel command line (kernel 7.0+) | [KB-0021](kb/issues/KB-0021-netboot-installer-tmpfs-full.md) |
| apt: "Release file is not valid yet" after the host slept | Nested VMs froze with the hypervisor and woke ~5 h behind; chrony's default `makestep 1 3` only steps the clock at startup | `makestep 1 -1` everywhere | [KB-0026](kb/issues/KB-0026-nested-vm-clocks-hours-behind.md) |
| `ansible-pull` fails to clone | The first in-lab git server was plain nginx ("dumb HTTP"), which can't serve shallow clones | `--full` at first; now workstations pull from GitHub, which can | [KB-0028](kb/issues/KB-0028-ansible-pull-shallow-clone-dumb-http.md) |
| DHCP server's DNS updates REFUSED | AD DNS name objects are owned by whoever created them, including empty "tombstoned" ones left by earlier client self-registration | Single writer (the DHCP service account); clients don't register | [KB-0029](kb/issues/KB-0029-ad-dns-updates-refused-stale-dnsnode.md) |
| Every Ansible run "changed" sssd.conf and restarted SSSD | `sssd.service` resets `/etc/sssd` to `root:sssd`, group-readable, on every start; the role wrote `0600` | Write `root:sssd 0640`, matching what the service enforces | [KB-0030](kb/issues/KB-0030-sssd-conf-changed-every-run.md) |
| First boot and later runs disagreed about the machine's AD groups | Refreshing local facts mid-play is unreliable in ansible-core 2.20, and the old fact names are deprecated | The role runs the AD lookup directly and stores it in one variable | [KB-0031](kb/issues/KB-0031-ad-groups-from-local-facts-unreliable.md) |
| Reimaged VM reinstalled itself 8 times | The first reimage script used `qm disk unlink`, which also removes the disk from the boot order, so the VM kept PXE-booting | The VM definition sets its boot order explicitly | [KB-0032](kb/issues/KB-0032-qm-disk-unlink-dropped-boot-order.md) |
| Installer: kernel panic, "System is deadlocked on memory" | A ballooning range let Proxmox shrink the VM mid-install; the installer's RAM-held ISO can't be given back | Fixed memory (no balloon range). Workstations no longer run the installer at all (golden image) | [KB-0022](kb/issues/KB-0022-balloon-shrank-vm-mid-install.md) |
| A reimage held the OpenTofu state lock for 15 minutes | The provider waits up to 15 minutes for the guest agent; an installing or crashed VM has none | `agent.timeout = "30s"`, and `stop_on_destroy` so a crashed VM is powered off instead of waited on | [KB-0033](kb/issues/KB-0033-opentofu-lock-held-waiting-for-agent.md) |
| Configuration runs failed after an SSH policy change | Ubuntu starts `ssh.service` on demand (`ssh.socket`), so `systemctl reload ssh` fails while it isn't running | `systemctl try-reload-or-restart ssh` | [KB-0034](kb/issues/KB-0034-ssh-reload-fails-socket-activated.md) |
| The first portal-built machine stopped at "An error occurred" | The old shell `lab` found new machines with `comm`, comparing a locale-sorted list with a Python-sorted one; `ws-tester` sorted differently in each, so it never got a one-time password | Byte-order sort at the time; `lab` is Python now and works from the OpenTofu plan itself | [KB-0035](kb/issues/KB-0035-locale-sort-hid-hyphenated-guests.md) |
| Browser terminal filled with `start=…;machineid=…` on every prompt | systemd's new profile script prints OSC 3008 "context" escape codes, which Guacamole's terminal shows as text | `dpkg-divert` the script on workstations | [KB-0036](kb/issues/KB-0036-osc-3008-garbles-browser-terminal.md) |
| Second "Connect" showed "No recent connections" | Guacamole reused the browser's existing session and ignored the new signed login, whose connection list had expired | The portal signs out the old Guacamole session before each connect | [KB-0037](kb/issues/KB-0037-guacamole-reused-stale-session.md) |
| 502 from the VPS after turning on upstream certificate checks | nginx's `proxy_ssl_verify_depth` defaults to 1, too short for a Let's Encrypt chain | `proxy_ssl_verify_depth 2` | [KB-0038](kb/issues/KB-0038-vps-502-ssl-verify-depth.md) |
| Admin sign-in made the browser ask for the demo password again | Behind HTTP Basic auth, a 401 from the app makes browsers discard the cached credentials | The app answers 403, never 401 (Basic auth was later replaced by a sign-in page) | [KB-0039](kb/issues/KB-0039-401-dropped-basic-auth-credentials.md) |
| Admin sign-in failed: "Missing Authority Key Identifier" | Python 3.13+ checks certificates strictly, and Samba's auto-generated LDAPS certificate lacks that extension | A Let's Encrypt certificate for dc01 (`dc01.lab.radicallydecent.com`) | [KB-0040](kb/issues/KB-0040-samba-ldaps-cert-rejected-python-313.md) |
| First portal deletion left records behind | Clean-up matched MAC links by `lnk_source`, which `find` in ansible-core 2.20 no longer returns | Match links by name. (Workstations no longer have install records at all.) | [KB-0041](kb/issues/KB-0041-find-lost-lnk-source-cleanup-incomplete.md) |
| A worker restart could kill a build halfway | Builds ran as child processes of the portal's worker, and a deployment restarts the worker | Each operation runs in its own transient systemd unit (`lab-op-<id>`) | [KB-0042](kb/issues/KB-0042-worker-restart-killed-builds.md) |
| First clones of the golden image never finished booting | Proxmox's cloud-init network config names the NIC `eth0`; cloud-init can't rename the already-up `ens18`, and netplan then makes the boot wait for an `eth0` that never appears | The image does DHCP on any `en*` NIC itself and cloud-init networking is off; the DHCP reservation decides the address | [KB-0046](kb/issues/KB-0046-clones-hung-on-eth0-rename.md) |
| Clones booted fine but never enrolled | The first-boot unit was ordered after `cloud-final`, which itself runs after `multi-user.target`, the target that wants the unit: systemd found the cycle and dropped the unit | Order it after `cloud-config` (hostname already set) and make it `Type=simple` | [KB-0047](kb/issues/KB-0047-firstboot-unit-dropped-ordering-cycle.md) |
| Every page of `lab.` and `pve.` answered 503 | A Proxmox tab with an expired session polled the API; each poll was redirected to the sign-in page, whose rate limit counted page visits, so the tab used up the allowance shared by both sites | Count only sign-in POSTs, answer 429. (Changing the zone's key needed a new zone name: nginx refuses that on reload, logs `[emerg]`, and keeps the old config, though `nginx -t` passes) | [KB-0048](kb/issues/KB-0048-stale-proxmox-tab-exhausted-rate-limit.md) |
